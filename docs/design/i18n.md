# 国际化（i18n）：全端多语言与跟随系统切换

> 状态：方案定稿（2026-10-23），未实施。首期范围 Web + 苹果三端（iPhone/iPad、Mac、Apple TV）
> 及它们依赖的服务端能力；Android / Android TV / Windows / 鸿蒙后续复用同一套服务端与术语表。
> 关联文档：[metadata.md](metadata.md)（元数据语言）、[settings-ui.md](settings-ui.md)（设置页规范）、
> [domain-events.md](domain-events.md)（通知渲染）、[cloud-push.md](cloud-push.md)（推送）、
> [plugin-market.md](plugin-market.md) / [theme-plugins.md](theme-plugins.md)（插件与主题清单）。

## 0. 目标与成功标准

支持 **简体中文（zh-Hans）** 与 **英语（en）** 两种界面语言，**默认跟随系统 / 浏览器**，
用户可在符合各平台惯例的位置改选。

可验证的成功标准：

1. 浏览器语言为英语的新访客，从初始化页、登录页到登录后的所有页面看到的是英文，
   **包括服务端返回的报错**（如「密码错误」）。
2. iPhone / Mac / Apple TV 系统语言为英语时 App 全英文；系统语言为日语、德语等不支持的语言时回退英文。
3. 用户在 Web「外观与语言」里改为 English，**不刷新页面立即生效**，换浏览器登录同一账号仍是 English。
4. 英文 iPhone 收到的推送是英文，中文 iPhone 收到的同一事件推送是中文（同一账号两台设备各按各的）。
5. 现有中文用户在整个迁移过程中**零感知**：每个迁移 PR 合并前后中文界面逐字一致。
6. CI 阻止新增未走文案文件的中文（棘轮），阻止英文漏翻、占位符不一致。

不在本期范围：繁体中文（§9 给出低成本补齐路径）、从右到左语言、按用户切换影片元数据语言、
系统日志 / CLI / 代码注释的翻译。

## 1.5 核心决策一览

| # | 决策 | 理由（展开见对应章节） |
|---|---|---|
| D1 | **三端都以中文原文作为文案键**（Web `t("下载器")`、Swift `Text("下载器")`、Python `_("下载器")`） | 苹果 String Catalog 与 gettext 的标准做法；迁移只需包一层、不必给上万条文案起名；中文改动 = 键变化 = 英文自动标记待翻，杜绝「中文改了英文没跟上」；三端同一中文可以对齐同一英文 |
| D2 | **语言由客户端决定**，服务端从请求里读，不替客户端做主 | 平台惯例（苹果跟随系统、Web 跟随浏览器/账号）；所有端零成本复用 |
| D3 | 不支持的系统语言 → **英语**；所有 `zh-*` → 简体 | 德、日、法等用户看英文远比看中文友好；繁体用户读简体的门槛最低 |
| D4 | **Web 有应用内切换**（登录页 + 设置），**苹果端不做应用内切换**，设置里放一行跳系统的「单个 App 语言」 | 苹果人机界面指南的明确建议，系统级单 App 语言已覆盖；Web 没有系统级设置，必须自己提供 |
| D5 | 服务端渲染给**某台设备**的文字（App 推送）用该设备的语言；渲染给**某个人**的（IM、系统通知）用这个人的语言 | 推送在设备上看，跟设备一致最自然；IM 没有设备语境 |
| D6 | 新增落库的用户可见文字一律存 **文案键 + 参数**，读出时再渲染 | 否则切语言后历史记录永远是中文 |
| D7 | 影片元数据语言**本期不按人切换**，仍是管理员的全局设置；初始化时按管理员的浏览器语言给默认值 | 按人切换要多语言落库，属于 [metadata.md](metadata.md) 的后续演进 |
| D8 | 翻译由开发时的 Agent 按**术语表**生成，关键页面人工过目；不接第三方翻译平台 | 两种语言、开发主力是 Agent，平台的协作价值用不上；无需新增密钥 |

## 2. 语言解析：一条链路贯穿三端

### 2.1 语言标签

- 内部只认两个值：`zh-Hans`、`en`。用户偏好额外有 `auto`（跟随系统/浏览器）。
- 归一规则（所有端同一份，服务端 `movieclaw_api.i18n.negotiate()`、Web `lib/i18n/negotiate.ts`，
  两边各有一组同样的单测用例）：
  - `zh`、`zh-CN`、`zh-Hans*`、`zh-SG` → `zh-Hans`
  - `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant*` → `zh-Hans`（D3；繁体上线后改为 `zh-Hant`）
  - `en*` → `en`
  - 按 `Accept-Language` 的 q 值顺序取第一个能归一的；全部不能归一 → `en`

### 2.2 Web 的判定顺序

```
账号偏好（ui_prefs.language，非 auto 时）
  > 本浏览器的 cookie mc_locale（登录页选的、或账号偏好的镜像）
  > 浏览器 Accept-Language（navigator.languages 同源）
  > en
```

- 判定在 Next 服务端完成（`app/layout.tsx` 读 cookie + 请求头），结果写进 `<html lang>` 并
  注入客户端，首帧就是正确语言，不闪烁。
- 登录后拉到账号偏好：与 cookie 不一致时以账号为准并回写 cookie。

### 2.3 服务端的判定（请求上下文）

一个纯 ASGI 中间件（遵守 #172：不用 BaseHTTPMiddleware）解析后放进 contextvar `current_locale`：

```
cookie mc_locale（只有 Web 会带，覆盖 SSE / <img> / EventSource 这类设不了请求头的请求）
  > Accept-Language
  > en
```

- Web 的 API 客户端在每个 fetch 上显式设置 `Accept-Language: <已判定语言>`（该头不是
  浏览器禁止设置的头），保证「浏览器是中文、账号选了英文」时报错也是英文。
- 苹果端不需要任何改动：URLSession 默认按 **App 实际生效的本地化** 发送 `Accept-Language`
  （P0 实测确认；若不成立，在 API 客户端统一补一个头）。

### 2.4 服务端主动发出的文字用谁的语言（D5）

| 场景 | 语言来源 |
|---|---|
| App 推送（APNs / 云推送） | 目标设备 `login_device.locale` |
| IM 推送、Webhook 的可读文本、系统通知、Agent 后台任务回报 | 成员 `ui_prefs.language`（非 auto）> 该成员最近一次请求的语言 `last_locale` > `zh-Hans`（存量用户兜底） |

- `login_device` 新增 `locale`、`timezone` 两列；每次带令牌的请求若与库里不同才写（按设备限频，
  遵守「统计不碰盘」的精神：值不变不写）。`timezone` 用于推送里出现的绝对时间（如「今晚 20:00 更新」）。
- 成员（含超管）新增 `last_locale`，同样只在变化时写。
- 旧客户端不带新信息也没关系：`Accept-Language` 本来就有，字段为空时按兜底链走。

## 3. 语言设置入口（产品设计）

原则：

1. **默认零操作**：首次使用就按系统 / 浏览器选对语言，绝大多数人永远不用找入口。
2. **看不懂当前语言的人也能找到入口**：地球图标 + 语言**自称**（「简体中文」「English」），
   不用国旗（国旗代表国家不代表语言），不用当前语言去翻译其它语言的名字。
3. **符合平台惯例**：苹果用系统的单 App 语言设置；Web 没有系统级设置，才自己提供。
4. **个人偏好，不是服务器配置**：放在「账号」组，成员与超管都能改，各管各的；
   不在「系统」组放全局界面语言。
5. **不增加设置项**（工具栏/设置密度偏好）：不单独做「地区格式」「时区」设置，日期数字格式跟语言走，
   时区跟浏览器 / 系统。

### 3.1 Web

**入口 1：登录页与初始化页（登录前）**
- 卡片下方一个轻量文字按钮：`🌐 English ▾` / `🌐 简体中文 ▾`，点开为两项列表。
- 只写 cookie `mc_locale`，不需要账号。这是「误入陌生语言界面」的人唯一需要的逃生口。

**入口 2：设置 → 账号 → 「外观与语言」（登录后）**
- 现有「外观」分区（成员可见）改名「外观与语言」，描述改为「语言、首页背景与界面质感」，
  **语言卡片放在最上面**。不新开分区。
- 选项（单选列表，与现有设置控件同一组件）：

  ```
  语言
  ○ 跟随浏览器 · English        ← 副文案显示当前实际生效的语言
  ○ 简体中文
  ○ English
  ```

- 选中即保存到 `ui_prefs.language` 并回写 cookie，`router.refresh()` + 切换客户端文案，
  **不整页刷新**、不丢正在播放的状态。
- 不放在用户头像菜单 / 顶栏：切换是一次性操作，顶栏密度优先。

### 3.2 iPhone / iPad

- 设置页「通用」区加一行：`语言    简体中文 ›`（右侧显示 `Bundle.main.preferredLocalizations.first`
  对应的自称）。
- 点按打开 `UIApplication.openSettingsURLString`，即系统设置里 MovieClaw 自己的页面，
  其中有系统提供的「首选语言」。系统改完会自动重启 App，无需我们处理。
- 行下方脚注：「在系统设置中为 MovieClaw 单独选择语言。」系统只在设备语言列表里有两种以上语言时
  才显示该选项，脚注补一句「若没有该选项，请先在『通用 → 语言与地区』添加语言」。
- 不做应用内语言切换（D4）。

### 3.3 Mac

- 设置窗口「通用」加同样一行，点按打开 系统设置 → 通用 → 语言与地区（在「应用程序」列表里为单个
  App 选语言），深链 URL 在 P0 实测确认。脚注说明「重新打开 MovieClaw 后生效」。

### 3.4 Apple TV

- 跟随系统语言。tvOS 是否提供单 App 语言没有查到官方说明，P0 在 tvOS 26 上实测：
  - 有 → 与 iPhone 相同，加一行跳系统设置；
  - 没有 → **不加任何入口**（不做只读展示行，避免占焦点位）。

### 3.5 后续端（预留口径）

- Android / Android TV：Android 13+ 系统单 App 语言（`localeConfig`），做法同苹果；
  低版本系统与 Windows / 鸿蒙按 Web 的做法放在「设置 → 通用 → 语言」。

## 4. Web 方案

### 4.1 选型：i18next + react-i18next + i18next-icu，中文原文作键

- **为什么不是 next-intl**：它以 `a.b.c` 结构化键为中心，点号是命名空间分隔符，中文原文作键
  不是它的用法；给 9,000 行文案逐条起名，迁移成本和评审噪音都翻倍。
- **为什么不是 Lingui**（同样是原文作键、PO 格式、开发体验最好）：在 Next 下依赖实验性的 SWC 插件，
  插件版本必须和 Next 内置的 SWC 精确匹配，**每次升级 Next 都可能被卡住**。
- **i18next**：最广泛使用的 JS i18n 库，官方支持自然语言键（`keySeparator: false`、
  `nsSeparator: false`）、找不到翻译时回退到键本身；纯运行时，不碰构建链；服务端组件里按请求
  `createInstance()`，客户端组件用 `react-i18next`；`i18next-icu` 提供 ICU 复数与选择。
- 实现形态：

  ```tsx
  const { t } = useT();                 // 客户端组件
  const t = await getT();               // 服务端组件
  t("下载器")
  t("已加载 {count} / {total} 部影片", { count, total })
  t("播放", { context: "noun" })        // 同一中文需要不同英文时用上下文区分
  <Trans>点击 <Link href="/settings">设置</Link> 继续</Trans>
  ```

- **中文不需要资源文件**：键就是中文，`zh-Hans` 直接回退到键；只有英文要下发资源。
- 英文资源按模块拆文件 `apps/web/locales/en/<模块>.json`（`player`、`library`、`settings-*`…），
  ① 并行迁移的 PR 不会在同一个大 JSON 上冲突；② 按路由懒加载，首屏只拉用到的模块。
- 参数占位一律 ICU 风格 `{name}`；英文复数写在译文里：
  `"已加载 {count} 部影片": "{count, plural, one {# movie} other {# movies}} loaded"`。

### 4.2 格式化

- `lib/time.ts`：`TIME_DISPLAY_CONFIG` 改为按语言取值；dayjs 按语言加载 `zh-cn` / `en`；
  `M月D日` 这类写死的格式改为 `Intl.DateTimeFormat` 的组件选项（`{month: "short", day: "numeric"}`），
  中文仍得到「10月23日」。
- 新建 `lib/i18n/format.ts`：数字（含中文「万/亿」→ `Intl.NumberFormat` 的 `compact` 写法，
  英文自然得到 `1.2K`）、文件大小、时长（`1 小时 23 分` ↔ `1 hr 23 min`）、列表连接
  （`、` ↔ `, and`）。37 处 `toLocaleString` 收口到这里。
- 时区不变：仍按浏览器本地时区（见既有时间处理规则）。

### 4.3 容易被忽略的细节

- **中文字体选择**：`<html lang="en">` 时，部分系统（Windows / Linux 的 Chrome）会给片名里的
  汉字挑日文字形。字体栈显式写上 `"PingFang SC", "Noto Sans SC", "Microsoft YaHei"`，
  并给来自元数据的标题、简介元素加 `lang` 属性（取媒体的元数据语言）。
- **英文更长**：通常长 30%～60%。重点排查工具栏、筛选条、按钮组、表格列、卡片标题的固定宽度；
  宁可折行或收进「⋯」，**不缩小字号**。
- **标点与排版**：中文直角引号「」、全角冒号逗号不能出现在英文译文里（CI 校验）；
  英文用 sentence case（只首字母大写），按钮用动词开头。
- **不能包 `t()` 的中文**：做识别、匹配、解析的中文（种子标题里的「第1集」「全集」正则、
  拼音搜索、豆瓣字段名、和后端约定的值、测试夹具）是数据不是文案。迁移脚本先分类，
  只包文案；数据类加 `// i18n-ignore` 或放进白名单文件。
- **PWA 清单**：`app/manifest.ts` 的 `name/description` 按请求语言输出。
- **缓存**：Next 的请求缓存、SWR 缓存中凡是含翻译后文本的，键里要带语言。
- **开发用伪语言**：`?locale=pseudo` 时把译文变成加长的带变音英文（`[Ðöŵñłöåð ‧‧‧]`），一眼看出
  漏包的中文和会截断的布局；仅开发模式可用。

## 5. 苹果方案

### 5.1 String Catalog，中文作源语言

- 保留 `developmentLanguage: zh-Hans`，键就是中文原文。现有 `Text("设置")` 一行不改，
  只在 catalog 里补英文。
- `String` 类型的文案改为 `String(localized: "…")`；枚举的显示名、视图模型里的文案优先用
  `LocalizedStringResource`，到界面再解析，切语言不会残留旧值。
- 插值：`Text("已加载 \(count) 部影片")` 会自动成为带 `%lld` 的键，英文复数在 catalog 里用
  「按复数变化」配置，不写 if。
- 不要用 `Text(verbatim:)` 或 `Text(someString)` 去承载文案（不会被提取）；数据类字符串
  （片名、文件名）才用这两种。

### 5.2 工程配置（project.yml / XcodeGen）

- `CFBundleLocalizations` 增加 `en`；`knownRegions` 增加 `en`；打开 `SWIFT_EMIT_LOC_STRINGS`、
  `LOCALIZATION_PREFERS_STRING_CATALOGS`。
- **回退到英文**（D3）：`CFBundleDevelopmentRegion` 从 `$(DEVELOPMENT_LANGUAGE)` 改为显式 `en`，
  catalog 源语言仍为 zh-Hans。系统在用户语言列表里找不到支持的语言时回退到 `CFBundleDevelopmentRegion`。
  这一组合需 P0 实测（日语系统 → 英文；中文系统 → 中文；系统界面如画中画、权限弹窗按钮跟随 App 语言）。
  若实测不可行，退路是源语言保持 zh-Hans 并接受「不支持的语言回退中文」，记入实施记录。
- 注意：苹果的回退是**按整个 bundle**而不是按单条文案——英文里漏翻的条目会直接显示中文键，
  所以 §8 的漏翻检查是硬门槛。
- catalog 布局：
  - `Shared/Localizable.xcstrings`：Shared 以源码编进 iPhone / Mac / TV 三个 App，一份覆盖三端。
    多 target 共用一份 catalog 时，Xcode 是否把「本 target 没用到的条目」误标为过期，P0 实测；
    若会，则改为每个 App 一份 catalog，用脚本同步 Shared 部分。
  - `AetherCore`（独立 framework）单独一份，取文案时写明自己的 bundle（`#bundle` / `bundle: .module`）。
  - 通知扩展、TopShelf 扩展各一份；`InfoPlist.xcstrings` 负责权限说明（相机、本地网络、相册）。
- **xcstrings 合并冲突**：它是 Xcode 整体重写、键排序的 JSON，并行 PR 必冲突。苹果端迁移 PR
  **按模块串行合并**；另备 `scripts/i18n/xcstrings-merge.py`（按键合并两份 catalog）用于变基时解决冲突。

### 5.3 格式化

- 28 处 `DateFormatter`：能用 `.formatted()` 的改用它；必须定制的用
  `setLocalizedDateFormatFromTemplate`，不写死 `yyyy年M月d日`。
- 相对时间、数字、文件大小、时长分别走 `RelativeDateTimeFormatter`、`.formatted()`、
  `ByteCountFormatStyle`、`Duration.formatted()`，集中在一个 `Formatting.swift`。
- 现有断言中文输出的单元测试（如 `ShellLogicTests` 的「几秒前」）显式固定 `Locale(identifier: "zh-Hans")`，
  再补同一组英文用例。

### 5.4 测试

- 方案里加一个英文测试计划：`-AppleLanguages (en) -AppleLocale en_US`。
- 现有 UI 测试大量按中文 label 找元素：中文计划照旧跑；英文计划只挑关键流程，
  **新写的用 `accessibilityIdentifier`**，不批量改造存量测试。
- 排版检查用 Xcode 内置的「双倍长度伪语言」和「从右到左伪语言」以外的英文实测截图；Apple TV 重点看
  焦点放大后的卡片标题截断。

### 5.5 上架

- App Store Connect 增加英文本地化：名称、副标题、描述、关键词、截图、「新功能」。
- 发版技能（`.claude/skills/release`）的 TestFlight「测试内容」与商店「新功能」改为中英两份。
- 隐私政策补英文版（App Store 英文页面引用）。

## 6. 服务端方案

### 6.1 机制

- 新模块 `movieclaw_api/i18n/`：
  - `negotiate()`（§2.1）、`current_locale` contextvar、纯 ASGI 中间件（§2.3）；
  - `_()`：gettext 语义，msgid 是中文原文，`_("找不到 {name}", name=x)`；在请求上下文里按
    `current_locale` 翻译，在后台任务里用 `with use_locale(loc):` 显式指定；
  - 目录 `src/movieclaw_api/locale/en/LC_MESSAGES/messages.po`，用 Babel 提取与编译（PO 是业界标准，
    Python 生态现成工具链）。
- **报错**：`AppException` 的 handler 在序列化前统一翻译 `message`。886 处 raise 先**不用改**——
  不带参数的中文原文直接就是 msgid；带 f-string 的改写为 `_()` 形式才能翻译（分批）。
  不改为「每种错误一个细分 code、各端自己翻译」：那样每个客户端都要维护映射表。
- **接口里的名称**（约 98 处 `label` 等）：在构造响应时用 `_()`；涉及缓存的响应（`movieclaw_cache`、
  HTTP 缓存）键里带语言，或响应头加 `Vary: Accept-Language`。
- **第三方原文透传**：qBittorrent、TMDB、站点返回的错误原样展示，不翻译。

### 6.2 落库文字（D6）

- 新写入的用户可见文字（系统通知、任务失败原因、事件通知）存 `message_key` + `message_params`（JSON），
  读出时按读者语言渲染。
- 存量行：读出时把整段文字当 msgid 查一次——不带参数的老消息自动得到英文；查不到就原样显示中文。
  不做数据迁移。

### 6.3 推送、IM、通知

- 推送：按目标设备 `locale` 分组渲染（同一事件对中文设备、英文设备各渲染一次）。不改用 APNs 的
  `loc-key` 让设备端翻译——服务端渲染对所有推送通道（官方云推送、IM、未来的安卓）一致。
- 推送里的绝对时间用 Babel 按设备 `locale` + `timezone` 格式化。
- 「测试通知」等固定文案同样走 `_()`。

### 6.4 Agent

- 系统提示追加一句「使用 {语言名} 回复用户」，语言取自会话发起请求的 `current_locale`；
  IM 入口取成员语言（§2.4）。会话标题生成同理。
- 工具描述、技能、提示词主体保持中文（模型读得懂，且这是开发者内容）。

### 6.5 内容语言（不随界面语言变化）

- 影片元数据语言仍是全局 `tmdb_language`（D7）；**初始化向导**创建超管时，按其浏览器语言预设
  （`en` → `en-US`，中文 → `zh-CN`），之后在「刮削与整理」可改。不新增向导步骤。
- 默认字幕 / 音轨仍按库语言（`track_policy.py`），保持现状。
- 豆瓣数据源只有中文，照旧。

## 7. 插件与主题（P4）

- 清单（`manifest`）的 `name`、`description`、设置项的 JSON Schema `title/description`
  支持多语言：采用 W3C Web App Manifest 正在推进的 `translations` 字段写法
  （`"translations": {"en": {"name": "…", "description": "…"}}`），优先业界标准而不自造格式；
  插件市场索引一并携带。
- 插件网页、主题通过请求头与 `<html lang>` 拿到当前语言；插件 SDK 暴露 `ctx.locale`。
- 插件开发技能、示例插件补「如何提供英文」一节。

## 8. 质量门槛（CI 与端到端）

| 检查 | 内容 |
|---|---|
| 中文棘轮 | 脚本统计 Web（TS 语法树里的字符串与 JSX 文本）、Swift、服务端用户可见路径中**未经 `t()/_()/Text/String(localized:)` 的中文**，基线存 `scripts/i18n/baseline.json`，数量只许减不许增；`i18n-ignore` 标注与白名单可豁免 |
| 漏翻 | Web：代码里提取的键 ⊆ 英文资源；苹果：xcstrings 中 en 状态不得为 `new` / `needs_review`；服务端：PO 无空 msgstr、无 fuzzy |
| 占位符一致 | 每条译文的 `{var}` / `%lld` 集合与源文一致；ICU 语法可解析 |
| 英文卫生 | 译文中不得出现汉字与全角标点 |
| 跨端一致 | 汇总三端的「中文 → 英文」对，同一中文在不同端译法不同则告警；术语表里的词必须用规定译法 |
| 单测 | 语言归一与判定优先级（服务端、Web 同一组用例）；格式化函数中英两套期望 |
| Web 端到端（Playwright） | ① `locale: en-US` 打开初始化页、登录页 → 英文，`html[lang=en]`；② 输错密码 → 英文报错；③ 登录页切到简体中文 → 登录后中文；④ 设置里切 English → 不刷新即生效，刷新后保持；⑤ 新开浏览器上下文（中文 Accept-Language）登录同一账号 → 仍是英文；⑥ 关键页面中英截图对比，查截断溢出 |
| 苹果端到端 | iPhone / Mac / TV 英文测试计划跑关键流程并截图；日语系统 → 英文；设置里「语言」行打开系统设置；英文设备注册推送后，服务端「测试通知」载荷为英文 |
| 新旧搭配 | 旧客户端 × 新服务器（不带新字段、按 Accept-Language 照常工作），新客户端 × 旧服务器（报错仍是中文，不崩） |

## 9. 翻译工作流与术语

- **术语表** `docs/i18n/glossary.md`：产品词的规定译法与不译词，例如
  洗版 → upgrade / re-grab（定一个）、刷流 → ratio boost、追新 → follow new episodes、
  原盘 → Blu-ray disc / BDMV、片源 → release / source、转码器 → transcoder、
  MovieClaw、TMDB、qBittorrent 不译。先定 50～100 个核心词再开始批量迁移。
- **生成**：迁移 PR 里由 Agent 按术语表 + 所在文件上下文翻译；苹果 catalog 写注释（comment）给
  上下文；同一中文已有译文的直接复用。
- **评审**：每个 PR 附中英关键页面截图；首页、详情、播放器、登录、初始化这几页人工通读英文。
- **繁体（后续可选）**：用 OpenCC（简→繁 + 台湾用词）从简体自动生成 `zh-Hant`，三端都是
  「多一份资源」的成本，届时把 §2.1 的繁体归一改为 `zh-Hant`。

P2 内部串行（xcstrings 冲突）。

| 期 | 内容 | 验证 |
|---|---|---|

## 11. 风险

| 风险 | 应对 |
|---|---|
| 迁移误包了「数据类」中文，导致识别 / 匹配逻辑失效 | 分类先行 + 每个 PR 跑该模块全部单测；种子标题解析、搜索等模块列入人工复核清单 |
| 英文长度撑破布局 | 伪语言 + 英文截图评审；P1 每个 PR 必附 |
| xcstrings 并行冲突 | 苹果 PR 串行 + 合并脚本 |
| 回退英文的苹果组合不可行 | 退路见 §5.2，影响面仅「不支持语言的用户看到中文」 |
| 服务端缓存串语言 | 缓存键带语言 / `Vary`；P3 加用例：同一接口先英文后中文请求结果不同 |
| 规模大、周期长，期间新代码继续写中文 | P0 即上棘轮，从第一天起新增文案必须走 `t()` |
