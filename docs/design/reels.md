# 刷片：沉浸式竖滑看片段

> 状态：一期开发中（2026-09-29 起，分支 `feat/reels`）。入口先放在 iOS 媒体库顶栏做试验，页名「片段」。

## 1. 要解决什么

在自己的片库里像刷抖音一样上下滑：每滑一下，出现一部电影或一部剧里的一段 30～60 秒的片段；
看得有意思就横过手机或点「接着看」，**同一个播放器**直接往下放正片。目的是帮用户决定「今晚看
什么」「想重温哪部」，不是让人在信息流里消磨时间。

同类产品：Netflix Fast Laughs（2021，15～45 秒）、Tubi Scenes（2024，60～90 秒）、
Disney+ Verts（2026-03）、Netflix Clips（2026-04，横过手机直接看）。它们靠人工策展或海量
行为数据挑片段；我们两样都没有，所以靠**容器索引里的免费信号 + 硬护栏**。

## 2. 一期的决定（用户拍板）

| 问题 | 决定 |
|---|---|
| 预先剪好小文件，还是实时从原片放 | **实时**：挑好位置，用现有自研引擎从原片中间起播。预渲染要先把全库跑一遍（估算 5～18 小时）才好用，首日体验差 |
| 看没看过要不要区别对待 | 不区别，一期不看观看状态 |
| 剧集怎么抽 | **按剧抽**（一部剧一个名额），剧内随机一集 |
| 入口 | iOS 媒体库顶栏一个按钮，点开全屏沉浸页 |
| 网络 | 不限制；蜂窝网络进入前确认一次「可能很耗流量」 |
| 接口 | 要能轻松兼容将来的预剪模式（见 §5） |

## 3. 挑哪一段（服务端，零解码）

实现：`movieclaw_playback/container_index.py`（读索引）+ `services/reels/picker.py`（挑点）。

**只读索引，不解码、不通读文件**：

- MKV：SeekHead 定位 Info / Tracks / Chapters / Cues。Cues 里有每个视频关键帧的 Cluster
  字节位置，mkvmerge 还默认给**每条字幕事件**（包括 PGS 图形字幕）写索引点。
- MP4：只读 moov 的样本表（stts / stss / stsz / stsc / stco）。**不能用 ffprobe 列包**——它会
  顺带读出每个包的数据，等于通读 mdat（NAS 实测 15.7 GB 的 MP4 读了 60 秒、5.7 GB 仍未完）。
- 其余容器（TS、原盘目录、镜像）一期跳过。

NAS 实测（17 个文件）：MKV 每部读 0.2～2 MB、0.04～1 秒；MP4 每部读 2.5～16.5 MB（moov）、
0.14～1 秒；挑点本身几毫秒。

**规则**：

1. 区间：电影全片 5%～75%，剧集单集 10%～80%（不剧透、避开前情提要 / 片头曲 / 片尾曲 / 下集预告）。
2. 码率信号：45 秒窗口的码率 = 两端关键帧字节位置之差 ÷ 时间差。窗口最高码率比中位数高
   8% 以上才信它，取最高的窗口。
3. 信号平（网络平台的剧集常见近恒定码率，实测《黑袍纠察队》每个窗口都在 17.0～17.1 Mbps）
   就退回：区间前三分之一附近的章节起点；没有章节就取那个位置。
4. 起点：落在关键帧上；附近有章节起点就对齐章节（场景开头）；否则找前后没有台词的关键帧。
   字幕只知道事件时间，按「持续到下一条或最多 3 秒」估计台词持续期。
5. 终点：在起点后 30～60 秒里找离 45 秒最近的台词空隙。
6. 黑场：抓起点那一帧当封面，平均亮度低于 16（0～255）就把起点往后挪到下一个关键帧（每次
   至少 2 秒，最多 3 次）——章节起点常是淡入黑场。

**实测效果**（抽帧肉眼核对）：动作片、动画片命中率高（《功夫熊猫》4/4、《流浪地球2》空间站
危机、《龙族》比武）；对白为主的喜剧挑得弱；不限区间时码率峰值会集中在高潮段（《让子弹飞》
4 段全在 73%～89%），所以区间上限必须卡住。已知漏洞：韩剧这类片头曲在 15%～20% 处的，片头
可能被挑中（《机智的医生生活》），一期接受；零解码比对两集找片头试过、不成立（码控使同一内容
字节数不同，恒定码率片处处假匹配），要精确识别得上音频指纹。

**缓存**：`data/cache/reels/<文件id>.json`（登记为 `cache.reels`，可清空，重建几乎无感），
按「文件大小 + 修改时间 + 算法版本」认账；封面随条目图片存放
（`<条目id>/reels/<文件id>/<起点毫秒>.jpg`，经 `/images/assets` 提供，沿用条目可见性校验）。

## 4. 翻页与预热

- 抽样单位是「部」：电影一部一个名额，剧一部一个名额（《哆啦A梦》一部就有两千多集）。
- 第一页服务端生成随机种子，App 翻页时带回 `seed` + `offset`；同一种子顺序固定，服务端无状态。
- 没算过的片段在一页里并行算，整页最多等 3 秒，超时的这一页先跳过、后台照常算完；返回一页后
  顺手在后台把下一页要用的片段算好。
- 同一文件并发请求共用一次计算；计算限 3 路，抓帧与章节图共用两路 ffmpeg 的闸。

## 5. 接口（为预剪模式留口子）

`GET /api/v1/reels?seed=&offset=&limit=10&modes=seek`

```jsonc
{
  "seed": 123, "next_offset": 10, "has_more": true,
  "items": [{
    "id": "rl_15693_1964254",                 // 片段标识：文件 + 起点，事件按它归并
    "title": { "media_item_id": 6813, "kind": "movie", "name": "…", "year": 2022, "rating": 8.1,
               "genres": ["动作"], "tagline": "…", "poster_url": "…", "backdrop_url": "…",
               "logo_url": null, "episode": null },
    "cover_url": "/images/assets/6813/reels/15693/0001964254.jpg?v=…",
    "segment": { "file_id": 15693, "start_ms": 1964254, "end_ms": 2002300, "method": "chapter" },
    "play": {                                  // 怎么放：按 mode 区分，字段都可空
      "mode": "seek",
      "stream_url": "/api/v1/playback/files/15693/stream?token=…",   // 按文件签发，12 小时
      "size_bytes": 64200000000, "audio_ordinal": 1,
      "subtitle": { "ordinal": 2, "language": "chi", "title": "简体", "codec": "hdmv_pgs_subtitle" },
      "prefetch": [ { "offset": 0, "length": 180000, "purpose": "head" }, … ]
    }
  }]
}
```

兼容规则：

1. App 用 `modes` 声明自己会放哪几种，服务端只发它会放的——老 App 永远收不到 `clip`。
2. `segment` 永远是原片时间轴：「接着看」= `start_ms` + 已播时长，事件、封面在两种模式下
   逻辑都不变。
3. 存储也拆开：一期只有挑点结果；将来预剪只是再加一份「渲染产物」指向它，挑点不用重做。
   `play` 是一个带 `mode` 的模型、各模式字段可空（生成的 Swift 模型最稳）。

`POST /api/v1/reels/events`：`{"events": [{"reel_id", "kind", "mode", "media_item_id",
"file_id", "position_ms", "watched_ms", "wait_ms", "detail"}]}`，kind 为
impression / first_frame / leave / complete / continue / open / fail。只写 `reel_event` 表
（成员级数据，删除成员时一并清理），**不写观看记录**。

取流令牌不带 device_id：刷片的取流不登记到活动页，也不写续播点与播放次数。

## 6. App 侧（iOS）

版式对齐 Instagram Reels / 抖音（2026-09-30 用户给参照图后改版）：

- 入口：媒体库顶栏「⋯」左边一个按钮，在媒体库导航栈里**压栈**打开「片段」（路由 `.reels`，
  站内路径 `/library/reels`）；蜂窝网络下先确认。**底部标签栏保留**，停在这页时不随滑动收起。
- 顶栏：不带返回键（再点一次「媒体库」页签回到首页——各页签「再点一次回根页」是这次一起加的
  iOS 惯例）；左上角是标题「片段」（不用系统大标题：它跟着滚动视图走，一滑就缩成正中的小字）；
  右上角一个玻璃胶囊「全部 ⌄」，选「全部」或某个类型（`GET /reels/genres` 列出本人能刷到的类型）。
- 画面：纯黑底，影片居中成横带（中心在屏幕 46% 高处）；没出第一帧前先显示封面。点画面暂停 /
  继续，放到终点停下，再点重播。信息流这一页锁竖屏，转手机不会把整页转横。
- 全屏：横带下方一个描边小胶囊「全屏观看」（TikTok 横屏视频的做法），点了整页转横看这一段。
  用的是**同一个播放器**，画面从横带挪到全屏层，不重新装载、不断声（`ReelFullscreenView`）。
  全屏层有这些控制：左上角退出和片名；底部是播放 / 暂停、进度与时间、「看全片」。
  点画面显示或隐藏控制层，放着的时候 3 秒后自动隐去。「看全片」横着直接进播放器页，方向锁
  不动，不会先转回竖屏再转过去。两处实现细节是模拟器实测踩出来的：
  - 画面容器不用播放器页的 `EngineSurface`。它每次更新都把画面抢回自己的容器，退出全屏的
    淡出途中全屏层又把画面抢走，横带就黑了。
  - 翻页区每页始终按竖屏尺寸排版。跟着横屏重排的话，转回竖屏后滚动位置会对不上原来那一条。
- 右下角一列**无底色**的白色图标按钮（不用毛玻璃，和画面融在一起）：收藏（落在整部）、播放
  （从当前位置转到播放器页，长按可选「从头看」）、已看（电影整部、剧集这一集）、分享（管理员
  生成分享链接；成员分享片名文字）。收藏 / 已看的初始状态随刷片接口给出，点击走播放器同一个
  标记接口。
- 左下角左对齐，四行，层级从强到弱（2026-09-30 嫌密后收紧）：
  1. 导演（剧集是主创）：小头像 + 名字 + 身份。取自与详情页同一张影人关系表，旧条目退回档案
     里的姓名。这一行对应 TikTok / Instagram 作者头像与名字的位置，点了进人物页。
  2. 片名，剧集后面跟弱一档的「第 N 季·第 N 集」。
  3. 年份 · 评分 · 类型。
  4. 一行简介：剧集是「集名｜分集简介」。放不下时末尾给「展开」，点开最多六行，底下垫渐暗。

  组与组之间留得比组内宽；字号只用两档，颜色只用白与 70% 白。最底下一条细进度线表示这一段的
  进度，右边是「在整部片里放到哪 / 整部片多长」（剧集是这一集），所以片长不再写进信息行。
- 播放：自研引擎从 `start_ms` 起播，起播即带上音轨与字幕序号；刷片模式**不上报进度**
  （`Features/Reels/ReelPlayer.swift` 直接用 `AetherPlayback`，不经过 `PlaybackController`）。
- 「播放」：按当前位置打开播放器页（`PlayRequest.startSeconds` + 同一个文件），从这一刻起才是正常
  播放、才记进度。播放器页是新的引擎实例，但片源字节缓存的键相同（文件 id + 大小），刷片下过的
  字节直接复用。播放器页盖上来时刷片收掉引擎，收起后当前这条重新起播。
- 预取：当前这条出第一帧后，把下一条的 `prefetch` 各段按字节范围下进引擎的片源字节缓存
  （补丁 P39）；再往后两条只取文件头与索引。
- 预起下一条（2026-09-30 加）：原来每滑一条都要现建引擎，打开、探测、建会话、出第一帧全部重来一遍。
  - **改法**：当前这条出画 1 秒后，且下一条的预取已下完，另建一个引擎把下一条装载到片段起点。
    装载好就停在那里，并停止往前下载（引擎的暂停下载开关，补丁 P23）。滑过去只需「播放」。
    换条时旧引擎先停声，半秒后再拆。拆引擎在主线程上要几十毫秒，不能赶在滑动收尾那一刻。
  - **实测**：iOS 27 模拟器，软件解码通路，字节都已预取，各 10 次换条取中位数。
    - 停稳到开播：139 → 36 毫秒。
    - 停稳到出画：184 → 79 毫秒。
    - 改前的构成：主线程同步拆旧引擎约 50 毫秒；新引擎的装载在主线程上排队约 75 毫秒才开始；
      装载本身约 50 毫秒。建引擎对象本身不到 1 毫秒。
  - **剩下的耗时**：软件通路装载好停着时不解第一帧（要播放后才解，约 45 毫秒）；旧引擎停声要调
    音频同步器，约 35 毫秒。
  - **真机主力通路（换封装进 AVPlayer）模拟器量不了**：模拟器硬解不了测试片，全走软件通路。
    作为参照，NAS 日志里真机正常播放从建好引擎到首帧是 0.23～0.7 秒（片中起播、含网络）。
    预起后 AVPlayer 停在起点通常已有第一帧，预期接近「滑过去立刻动」，**待真机验证**。
  - **代价**：同时多一个引擎（4K 杜比视界约 135MB 内存）。往回滑、一次跳过好几条时没有预起，
    退回现建引擎。
- 事件：攒一批报 `/reels/events`，含「滑到出画面」的等待时间。

## 7. 二期候选

- 让大模型读带时间戳的字幕挑「不剧透、单独成立的名场面」，补对白片的短板（索引已给出每条
  字幕的位置，按位置读几百个小块就能拿到台词，不用通读文件）。
- 片头片尾识别（音频指纹）；原盘 / 镜像支持；外挂字幕；按事件数据调长度与规则。
- 预剪模式（`mode=clip`）：离线渲染 720p 小文件（NAS 实测 4K HDR 源一段 105 秒、约 9 MB）。
